# Jadwal & Target Waktu

Belajar sambil sekolah atau bekerja berarti waktu tidak selalu ideal. Jadwal ini adalah panduan, bukan kontrak. Yang penting adalah ritme yang bisa dipertahankan.

## Asumsi

- 15–20 jam per minggu, sekitar 3–4 sesi.
- Satu sesi 90–120 menit.
- Total 600–900 jam untuk seluruh fase inti.

## Rencana 9–12 bulan

| Bulan | Fase | Milestone |
| --- | --- | --- |
| 1 | Fase 0 + Fase 1 | Expense Tracker CLI selesai dan bisa didemokan |
| 2–3 | Fase 2 | Inventory System dengan test dan package |
| 4–5 | Fase 3 | TaskFlow API ter-deploy dengan CI hijau |
| 6–7 | Fase 4 | Proyek expert dan technical writeup |
| 8–9 | Fase 5 | Proyek portofolio dan mulai melamar |
| 10–12 | Cadangan | Perbaikan portofolio, kontribusi OSS, wawancara |

:::info Kenapa ada bulan cadangan
Hampir semua orang molor. Menyiapkan waktu cadangan sejak awal membuat keterlambatan tidak terasa seperti kegagalan.
:::

## Ritme mingguan yang disarankan

| Hari | Aktivitas | Durasi |
| --- | --- | --- |
| Senin | Materi baru + latihan | 90 menit |
| Rabu | Lanjut materi + studi kasus mini | 90 menit |
| Jumat | Studi kasus utama | 120 menit |
| Sabtu | Refactor, test, catatan, commit | 120 menit |

Sesi pendek setiap hari lebih baik daripada maraton sekali seminggu.

## Contoh satu minggu di Fase 2

| Sesi | Target |
| --- | --- |
| 1 | Modul 2.4 bagian dasar OOP, latihan kelas pertama |
| 2 | Modul 2.4 bagian property dan dataclass |
| 3 | Studi kasus model domain keuangan |
| 4 | Test model, refactor, tulis catatan, commit |

## Milestone yang bisa diperiksa

- **Minggu 4:** program CLI pertama berjalan tanpa crash.
- **Minggu 10:** punya package dengan test dan coverage di atas 80 persen.
- **Minggu 20:** API bisa diakses publik dan pipeline CI hijau.
- **Minggu 30:** punya technical writeup yang bisa dibaca orang lain.
- **Minggu 38:** punya portofolio dengan demo dan README yang matang.

## Kalau hanya punya 5 jam per minggu

Perpanjang durasi menjadi 18–24 bulan. Jangan memotong fase. Yang dipotong:

- Latihan terbimbing tambahan.
- Proyek bonus.
- Eksplorasi library di luar daftar.

Yang tidak boleh dipotong:

- Studi kasus utama tiap fase.
- Test dan dokumentasi.
- Refleksi.

## Tanda jadwalmu terlalu ambisius

- Sering melewati sesi karena merasa tidak siap.
- Menyalin solusi hanya agar target minggu tercapai.
- Tidak pernah menulis catatan.
- Proyek menumpuk dalam keadaan setengah jadi.

Kalau ini terjadi, kurangi target per minggu, bukan target akhir.

## Tanda kamu bisa mempercepat

- Studi kasus selesai sebelum estimasi.
- Bisa menjelaskan materi tanpa membaca.
- Checklist terisi penuh tanpa menunda.
- Kamu mulai bosan karena materinya terlalu mudah.

Percepatan yang sehat: tambah tingkat kesulitan proyek, bukan melompati fase.
